Three failure modes. One gate.

Know what changed before you merge.

ToolRatchet compares tool surfaces and reports actionable differences instead of quietly guessing when a change is safe.

01 / COMPATIBILITY

Catch breaking contracts

Compare input and output schemas, required fields, enums, bounds, references, and tool renames. Unprovable cases are sent for human review.

02 / CONTEXT BUDGET

Put a ceiling on growth

Track per-tool and total token estimates. Set maximum budgets, cap percentage increases, or ratchet the budget so it can only go down.

03 / INTEGRITY

Surface suspicious text

Flag newly introduced hidden Unicode, instruction overrides, concealment language, possible exfiltration, credential-file references, and riskier tool hints.

Fits into your existing workflow

Record. Check. Review.

Use the CLI locally, then make the same checks part of continuous integration.

Terminalbash
# Install from the repository
pip install git+https://github.com/devXyi/toolratchet

# Capture the current surface
toolratchet lock -- python my_server.py

# Fail CI when changes need attention
toolratchet check -- python my_server.py
GitHub ActionsYAML
 - uses: actions/checkout@v4
 - uses: actions/setup-python@v5
   with:
     python-version: "3.12"
 - run: pip install toolratchet
 - run: toolratchet check
     --summary-file "$GITHUB_STEP_SUMMARY"
     --format github
     -- python my_server.py

The examples above are templates; replace my_server.py with your actual server command. See the repository README for supported source formats and options.

Designed to be conservative.
When a change cannot be proven safe, ToolRatchet raises a review signal rather than silently passing it.
Security is a process

Useful signals. Honest limits.

ToolRatchet inspects schemas and text, not what a server secretly does at runtime. Identical schemas can still hide changed behavior. Token counts are deterministic estimates unless an optional tokenizer is used.

Integrity checks are heuristics: a flag means a human should investigate, and a clean result is not a security audit.

Keep a human in the loop

Pair schema checks with tests, review flagged changes, and apply runtime controls where your threat model requires them.
